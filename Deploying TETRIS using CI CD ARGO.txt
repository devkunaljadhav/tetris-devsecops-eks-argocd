Tetris DevSecOps CI/CD Deployment Guide
========================================

Project: Tetris DevSecOps with Jenkins, SonarQube, Trivy, Docker, Terraform,
Amazon EKS, and Argo CD

Purpose
-------
This guide describes how to provision an Amazon EKS cluster and deploy the
Tetris application using a DevSecOps CI/CD workflow.

Deployment flow
---------------
1. The Tetris source code is stored in a GitHub repository.
2. Jenkins checks out the source code.
3. SonarQube performs static code analysis.
4. Trivy scans project dependencies and container images.
5. Docker builds and publishes a versioned application image.
6. Jenkins updates the image reference in the Kubernetes manifest repository.
7. Argo CD detects the manifest change and synchronizes it to Amazon EKS.
8. Kubernetes exposes the application through a LoadBalancer service.

Repository roles
----------------
Source repositories:
- devsecops-Tetris-V1: Tetris application version 1
- devsecops-tetris-v2: Tetris application version 2

Manifest repository:
- devsecops-Tetris-manifest: Kubernetes deployment and service manifests

Security requirements
---------------------
Do not place passwords, access keys, personal access tokens, or private keys in
this guide or in source control.

Use the following secret-management mechanisms:
- Jenkins Credentials: Docker Hub credentials, GitHub tokens, and SonarQube
  tokens
- AWS IAM Role: AWS permissions for the Jenkins EC2 instance
- Kubernetes Secrets or AWS Secrets Manager: application runtime secrets
- .gitignore: local secret and credential files

Rotate every credential that has previously been committed to Git or exposed
in build logs.

1. Infrastructure prerequisites
-------------------------------
Create an Ubuntu EC2 instance for Jenkins with the following minimum
characteristics:

- Ubuntu 24.04 LTS
- m7i-flex.large or an equivalent instance size
- At least 50 GB of storage
- SSH access restricted to an approved administration network
- IAM role with the minimum permissions required for Terraform and EKS
- Inbound access for TCP ports 8080 and 9000 only when directly required

Install the following tools on the Jenkins EC2 instance:

- Java
- Jenkins
- Docker
- Terraform
- AWS CLI
- kubectl
- Trivy
- SonarQube
- Jenkins Node.js plugin

2. Install Jenkins, Java, and Docker
------------------------------------
Update the operating system:

sudo apt update
sudo apt upgrade -y

Install Java 21, curl, and wget:

sudo apt install -y openjdk-21-jdk wget curl
java -version

Download and start Jenkins:

sudo mkdir -p /opt/jenkins
cd /opt/jenkins

if [ ! -f jenkins.war ]; then
  wget https://get.jenkins.io/war/2.552/jenkins.war
fi

sudo chmod 755 jenkins.war

nohup java -Djava.net.preferIPv4Stack=true -jar jenkins.war \
  > /opt/jenkins/jenkins.log 2>&1 &

Verify that Jenkins is running:

ps -ef | grep jenkins.war | grep -v grep

Open:

http://<EC2_PUBLIC_IP>:8080

Install Docker:

sudo apt-get update
sudo apt-get install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
"deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
| sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install -y \
  docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo usermod -aG docker ubuntu
sudo systemctl enable docker
sudo systemctl restart docker

3. Install Terraform, kubectl, AWS CLI, and Trivy
-------------------------------------------------
Install Terraform:

sudo apt install -y wget
wget -O- https://apt.releases.hashicorp.com/gpg \
  | sudo gpg --dearmor \
      -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] \
https://apt.releases.hashicorp.com $(lsb_release -cs) main" \
| sudo tee /etc/apt/sources.list.d/hashicorp.list

sudo apt update
sudo apt install -y terraform

Install kubectl:

sudo apt install -y curl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
kubectl version --client

Install AWS CLI:

curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" \
  -o "awscliv2.zip"

sudo apt-get install -y unzip
unzip awscliv2.zip
sudo ./aws/install
aws --version

Install Trivy:

sudo apt-get install -y wget apt-transport-https gnupg lsb-release
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key \
  | sudo apt-key add -

echo "deb https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" \
  | sudo tee -a /etc/apt/sources.list.d/trivy.list

sudo apt-get update
sudo apt-get install -y trivy libatomic1
trivy --version

4. Start and configure SonarQube
--------------------------------
Start SonarQube as a Docker container:

sudo systemctl enable docker
sudo systemctl restart docker

docker run -d \
  --name sonar \
  --restart unless-stopped \
  -p 9000:9000 \
  sonarqube:lts-community

Verify the container:

docker ps

Open:

http://<EC2_PUBLIC_IP>:9000

Sign in with the initial administrator account and immediately change the
default password.

Create a SonarQube token under:

Administration > Security > Users > Tokens

Store the token in Jenkins as a Secret Text credential with ID sonar-token.
Do not store or display the token in this guide or in pipeline source.

Configure a SonarQube webhook:

Administration > Configuration > Webhooks

Name:
Jenkins

URL:
http://<EC2_PUBLIC_IP>:8080/sonarqube-webhook/

6. Configure Jenkins credentials
--------------------------------
Create the following Jenkins credentials.

Docker Hub credentials
- Kind: Username with password
- Scope: Global
- ID: docker

GitHub credential
- Kind: Secret Text
- Scope: Global
- ID: github
- Use a fine-grained token with the minimum repository and write permissions
  required to update the manifest repository

SonarQube credential
- Kind: Secret Text
- Scope: Global
- ID: sonar-token
- Use the token generated in SonarQube

Add the SonarQube server under:

Manage Jenkins > System > SonarQube Servers

- Name: sonar-server
- Server URL: http://<EC2_PRIVATE_OR_PUBLIC_IP>:9000
- Authentication token: sonar-token

For reproducible deployments, replace personal usernames and repository URLs
with organization-owned accounts and approved repositories.

7. Create the EKS infrastructure pipeline
------------------------------------------
Create a parameterized Jenkins pipeline named EKS-PROVISION.

Add a choice parameter:

- Name: action
- Choices: apply, destroy

Before running the pipeline:
- Configure the Terraform backend in EKS_TERRAFORM/backend.tf.
- Replace the example S3 bucket name and region with project values.
- Configure the AWS credentials or attach an IAM role to the Jenkins instance.
- Verify that Terraform is available to Jenkins.

Example pipeline:

pipeline {
    agent any

    parameters {
        choice(
            name: 'action',
            choices: ['apply', 'destroy'],
            description: 'Provision or destroy the EKS infrastructure'
        )
    }

    stages {
        stage('Checkout') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/<OWNER>/devsecops-Tetris-V1.git'
            }
        }

        stage('Terraform Version') {
            steps {
                sh 'terraform version'
            }
        }

        stage('Terraform Init') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform init'
                }
            }
        }

        stage('Terraform Validate') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform validate'
                }
            }
        }

        stage('Terraform Plan') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh 'terraform plan'
                }
            }
        }

        stage('Terraform Apply or Destroy') {
            steps {
                dir('EKS_TERRAFORM') {
                    sh "terraform ${params.action} -auto-approve"
                }
            }
        }
    }
}

Run the pipeline with action=apply.

After provisioning, update the kubeconfig:

aws eks update-kubeconfig \
  --name <EKS_CLUSTER_NAME> \
  --region <AWS_REGION>

Verify cluster access:

kubectl get nodes
kubectl get namespaces

8. Create the Tetris application pipeline
-----------------------------------------
Create a Jenkins pipeline job for the Tetris application.
The pipeline should perform code analysis, dependency and image scanning,
container publication, and manifest update in a single auditable workflow.

Recommended stages:
1. Clean workspace
2. Checkout source code
3. SonarQube analysis
4. Quality gate
5. npm dependency installation
6. Trivy filesystem scan
7. Docker image build and push
8. Trivy container image scan
9. Checkout manifest repository
10. Update deployment image
11. Commit and push the manifest change
12. Archive scan reports

Example pipeline:

pipeline {
    agent any

    tools {
        jdk 'jdk25'
        nodejs 'node25'
    }

    environment {
        SCANNER_HOME = tool 'sonar-scanner'
        GIT_REPO_NAME = 'devsecops-Tetris-manifest'
        GIT_USER_NAME = '<GITHUB_OWNER>'
        DOCKER_IMAGE = '<DOCKER_OWNER>/tetrisv1'
    }

    stages {
        stage('Clean Workspace') {
            steps {
                cleanWs()
            }
        }

        stage('Checkout Source') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/<OWNER>/devsecops-Tetris-V1.git'
            }
        }

        stage('SonarQube Analysis') {
            steps {
                withSonarQubeEnv('sonar-server') {
                    sh '''
                        $SCANNER_HOME/bin/sonar-scanner \
                          -Dsonar.projectName=TetrisVersion1.0 \
                          -Dsonar.projectKey=TetrisVersion1.0
                    '''
                }
            }
        }

        stage('Quality Gate') {
            steps {
                waitForQualityGate abortPipeline: false
            }
        }

        stage('Install Dependencies') {
            steps {
                sh 'npm install'
            }
        }

        stage('Trivy Filesystem Scan') {
            steps {
                sh 'trivy fs --format table --output trivyfs.txt .'
            }
        }

        stage('Docker Build and Push') {
            steps {
                script {
                    withDockerRegistry(
                        credentialsId: 'docker',
                        toolName: 'docker'
                    ) {
                        sh """
                            docker build -t ${DOCKER_IMAGE}:${BUILD_NUMBER} .
                            docker push ${DOCKER_IMAGE}:${BUILD_NUMBER}
                        """
                    }
                }
            }
        }

        stage('Trivy Image Scan') {
            steps {
                sh """
                    trivy image --format table \
                      --output trivyimage.txt \
                      ${DOCKER_IMAGE}:${BUILD_NUMBER}
                """
            }
        }

        stage('Checkout Manifest Repository') {
            steps {
                git branch: 'main',
                    url: 'https://github.com/<OWNER>/devsecops-Tetris-manifest.git'
            }
        }

        stage('Update Manifest') {
            environment {
                NEW_IMAGE_NAME = "${DOCKER_IMAGE}:${BUILD_NUMBER}"
            }

            steps {
                withCredentials([
                    string(
                        credentialsId: 'github',
                        variable: 'GITHUB_TOKEN'
                    )
                ]) {
                    sh '''
                        sed -i "s|image: .*|image: ${NEW_IMAGE_NAME}|g" deployment.yml

                        git config user.email "jenkins@example.com"
                        git config user.name "Jenkins CI"

                        git add deployment.yml
                        git diff --cached --quiet ||
                            git commit -m "Update deployment image to ${NEW_IMAGE_NAME}"

                        git push \
                          https://${GIT_USER_NAME}:${GITHUB_TOKEN}@github.com/${GIT_USER_NAME}/${GIT_REPO_NAME}.git \
                          HEAD:main
                    '''
                }
            }
        }
    }

    post {
        always {
            archiveArtifacts(
                artifacts: 'trivyfs.txt,trivyimage.txt',
                allowEmptyArchive: true
            )
        }
    }
}

Important:
- The quality gate policy should be based on the project release requirements.
- Add an explicit Trivy exit policy when vulnerabilities must block deployment.
- Archive scan reports for audit and troubleshooting.
- Prefer a fine-grained GitHub token over a broad personal access token.

9. Install Argo CD
-------------------
Create the Argo CD namespace and install Argo CD:

kubectl create namespace argocd

kubectl apply -n argocd \
  -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

Verify the installation:

kubectl get pods -n argocd

For a production environment, restrict the Argo CD server to an approved
network or configure an ingress controller with TLS. For a temporary
demonstration, expose the server as a LoadBalancer:

kubectl patch svc argocd-server -n argocd \
  -p '{"spec":{"type":"LoadBalancer"}}'

Get the service address:

kubectl get svc argocd-server -n argocd

Retrieve the initial administrator password:

kubectl -n argocd get secret argocd-initial-admin-secret \
  -o jsonpath="{.data.password}" | base64 -d

Sign in using:
- Username: admin
- Password: the value retrieved from the Kubernetes secret

Immediately change the initial password and disable or remove the initial
administrator account in accordance with the organization security policy.

10. Connect the manifest repository
-----------------------------------
In the Argo CD UI:

1. Open Settings > Repositories.
2. Select Connect Repository.
3. Choose HTTPS.
4. Enter the manifest repository URL.
5. Enter credentials or configure a repository secret.
6. Confirm that the repository status is successful.

Create an application with the following values:

- Application name: tetris
- Project name: default
- Sync policy: Automatic
- Repository URL: <MANIFEST_REPOSITORY_URL>
- Revision: HEAD or main
- Path: .
- Cluster: https://kubernetes.default.svc
- Namespace: default

Recommended Argo CD settings:
- Enable self-heal
- Enable pruning
- Configure automated sync
- Create a rollback and recovery procedure

11. Deploy Tetris version 2
---------------------------
Create a second Jenkins pipeline for version 2 or parameterize the version 1
pipeline with a source repository and Docker image parameter.

Set:
- Source repository: devsecops-tetris-v2
- Sonar project key: TetrisVersion2.0
- Docker image: <DOCKER_OWNER>/tetrisv2
- Manifest repository: devsecops-Tetris-manifest

The version 2 pipeline must use the same stages as version 1:

- Source checkout
- SonarQube analysis
- Quality gate
- Dependency installation
- Filesystem scan
- Docker build and push
- Image scan
- Manifest update
- Git commit and push

Use the build number as the container image tag so every deployment can be
traced back to an exact Jenkins build.

After the pipeline completes, verify that the manifest commit updated
deployment.yml and that Argo CD reports the application as synchronized and
healthy.

12. Verification
----------------
Verify Kubernetes resources:

kubectl get nodes
kubectl get deployments -A
kubectl get pods -A
kubectl get services -A

Find the application LoadBalancer address:

kubectl get svc -n <APPLICATION_NAMESPACE>

Open the external DNS name or IP address printed by the service.

Test application pods directly:

kubectl logs -n <APPLICATION_NAMESPACE> deployment/<DEPLOYMENT_NAME>
kubectl describe pod -n <APPLICATION_NAMESPACE> <POD_NAME>

Verify Trivy reports:

find /var/lib/jenkins/workspace -name trivyfs.txt
find /var/lib/jenkins/workspace -name trivyimage.txt

The exact Jenkins workspace location depends on the Jenkins configuration.
Archived artifacts are the preferred source for completed build reports.

13. Operational recommendations
-------------------------------
- Use separate AWS accounts or clusters for development and production.
- Store Terraform state in an encrypted, versioned S3 bucket.
- Enable DynamoDB state locking when multiple operators use Terraform.
- Restrict IAM permissions and rotate credentials regularly.
- Pin tool and Kubernetes versions for reproducible builds.
- Configure HTTPS, DNS, and an ingress controller in production.
- Define pod CPU and memory requests and limits.
- Configure horizontal pod autoscaling for production workloads.
- Monitor Jenkins, EKS, Argo CD, and application logs with AWS or third-party
  monitoring tools.
- Apply vulnerability severity policies consistently across filesystem and
  image scans.

14. Cleanup
-----------
Destroy infrastructure using the parameterized Terraform pipeline with:

action=destroy

Before deleting AWS resources manually, confirm the status of:
- EKS cluster
- EC2 instances
- Elastic load balancers
- Kubernetes persistent volumes
- S3 Terraform state
- IAM roles and policies
- Elastic IP addresses
- CloudWatch resources

Remove Jenkins credentials, container registry credentials, and repository
tokens when they are no longer needed.
